# AurumQuant — 黄金强化学习交易系统 PRD v2.1

> 产品需求文档 · 2026-07-27 · 根据Sonnet审核意见修订

---

## 1. 产品定位

**一句话**：基于高频订单流数据建模 + PPO强化学习的黄金期货自动化交易系统。

### 核心理念

量化最核心的是对**高频订单数据**的建模，RL在其中扮演"交易决策者"角色：
- **订单流 → 状态表示**：从tick/LOB数据中提取市场微观结构特征
- **RL策略 → 交易决策**：PPO智能体根据状态输出最优仓位
- **PnL → 奖励信号**：以盈亏为核心的端到端优化

### 设计原则

1. **先基线，再RL**：在投入RL之前先用XGBoost/规则策略验证特征的预测力
2. **数据先行**：数据管道的质量和完整性决定RL训练的成败
3. **风控横切**：风控不是策略的子系统，而是横切所有层的约束
4. **诚实指标**：Sharpe目标基于真实CTA行业水平，非学术论文数字

### 2.2. 差距分析（vs 学术/业界前沿）

| 维度 | 当前实现 | 学术/业界标准 | 差距 |
|------|---------|-------------|------|
| 时序建模 | 无（MLP扁平向量） | LSTM/Conv1D/Transformer | ❌ 严重 |
| 状态维度 | 30维 | 63-140+ | ❌ 不足 |
| 多时间周期 | 无 | 日/4h/1h | ❌ 缺失 |
| 订单流特征 | 随机噪声模拟 | 真实tick/LOB数据 | ❌ 严重 |
| 奖励函数 | 纯PnL * 1e-6 | PnL + 交易成本 + 回撤约束 | ⚠️ 粗糙 |
| 样本外验证 | 无 | Walk-Forward / Purged CV | ❌ 红线 |
| 动作空间 | 12离散（低效） | 连续动作（Beta/Gaussian） | ⚠️ 低效 |
| 数据质量 | 无校验 | 清洗/异常检测/质控 | ❌ 缺失 |
| 基线对比 | 无 | 规则策略 / XGBoost | ❌ 缺失 |
| 回撤处理 | 硬截断15% | 渐进式惩罚 | ⚠️ 粗暴 |

## 3. 架构设计

```
┌──────────────────────────────────────────────────────────────────┐
│                       风控约束层（横切所有层）                   │
│  仓位限制 · 止损 · 日亏损上限 · 杠杆约束 · 连续亏损停交易       │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│                         数据层                                    │
│  CTP/SimNow Tick → 数据清洗/异常检测 → Parquet存储 → 特征工程   │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐                   │
│  │ Tick接收 │ → │ 清洗校验 │ → │ 特征计算 │                   │
│  │ (CTP)   │    │ (质控)   │    │ (量化)   │                   │
│  └──────────┘    └──────────┘    └──────────┘                   │
└─────────────────────────────┬────────────────────────────────────┘
                              ↓
┌──────────────────────────────────────────────────────────────────┐
│                      编码层                                      │
│  LSTM/Conv1D 时序编码器 → 多周期融合 → 特征拼接                 │
│  （保留MLP作为控制组，用于消融实验）                             │
└─────────────────────────────┬────────────────────────────────────┘
                              ↓
┌──────────────────────────────────────────────────────────────────┐
│                      RL策略层                                    │
│  PPO Agent (GAE+Clip) → 连续动作 → 仓位映射 → 执行              │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐                 │
│  │  Market    │  │  Actor     │  │  Slippage  │                 │
│  │  Encoder  │→│  + Critic  │→│  Model     │                 │
│  └────────────┘  └────────────┘  └────────────┘                 │
└─────────────────────────────┬────────────────────────────────────┘
                              ↓
┌──────────────────────────────────────────────────────────────────┐
│                      验证层                                      │
│  Walk-Forward → Purged CV → 对抗性验证 → 过拟合检测(DSR) → 报告 │
└──────────────────────────────────────────────────────────────────┘
```

### 数据架构要点

- **存储格式**：Parquet（列存、压缩、高效I/O）
- **存储粒度**：原始tick + 1min OHLCV + 特征数据三层分离
- **回放能力**：数据层需支持历史回放，确保训练和评估数据来源一致
- **数据校验**：每个批次写入前做完整性检查（缺失/跳变/异常值）

## 4. 需求范围

### Phase 1a — 数据基建（2-3周）

**目标：搭建可靠的数据管道 + 建立基线**

| 需求 | 说明 | 工作量 |
|------|------|--------|
| F-1a.1 真实订单流数据管道 | CTP/SimNow tick接入、清洗、Parquet落地 | 2-3周 |
| F-1a.2 数据质量监控 | tick缺失检测、跳变校验、异常值过滤 | 1周 |
| F-1a.3 多周期OHLC特征 | 日/4h/1h三个周期的OHLCV + 基础技术指标 | 3-5天 |
| F-1a.4 环境配置管理 | 所有超参/特征/风控参数集中管理，支持实验复现 | 2-3天 |
| F-1a.5 基线规则策略 | 动量+ATR通道突破策略，作为RL的baseline | 3-5天 |
| F-1a.6 XGBoost方向预测 | 用特征工程后的数据训练方向分类器，验证特征预测力 | 3-5天 |

**验收标准**：
- [ ] CTP/SimNow数据可稳定接入，日吞吐量>100万条tick
- [ ] 数据清洗管线通过回测验证（历史数据回放无遗漏）
- [ ] 基线策略年化Sharpe > 0.3（扣除交易成本后）
- [ ] XGBoost OOS方向准确率 > 53%（判定特征有预测力）

### Phase 1b — RL基础（2-3周）

**目标：让RL跑出可信的收益数字**

| 需求 | 说明 | 工作量 |
|------|------|--------|
| F-1b.1 Walk-Forward验证框架 | 时间序列切分：训练→验证→测试，超参独立优化，多fold | 1周 |
| F-1b.2 LSTM/GRU时序编码器 | 替换扁平MLP（保留MLP做控制组） | 3-5天 |
| F-1b.3 奖励函数重设计 | PnL + 交易成本 + 滑点 + 回撤渐进惩罚 | 3-5天 |
| F-1b.4 环境重置策略 | 黄金期货连续时间序列的episode切分（滚动窗口/事件驱动） | 2-3天 |
| F-1b.5 滑点模型 | 分时段（白天vs夜盘）差异化的滑点估计 | 2-3天 |
| F-1b.6 训练实验追踪 | metrics dashboard记录每次训练的Sharpe/DD/return | 2-3天 |

**验收标准**：
- [ ] Walk-Forward OOS Sharpe > 0.8（扣除交易成本）
- [ ] LSTM版优于MLP版（消融实验）
- [ ] 奖励函数收敛，Value loss稳定
- [ ] 在2020年疫情冲击和2022年加息周期下回撤 < 15%

**Phase 1总计：4-6周**

## 6. 约束条件

### 6.1 技术约束
- **合约**：AU（沪金），1000克/手，最小变动0.02元/克，保证金8%
- **训练数据**：最少5年历史tick数据，必要时扩展至10年
- **推理延迟**：信号生成 < 100ms（含特征计算）
- **数据存储**：Parquet格式，tick级原始数据+分钟级OHLCV+特征数据三层分离
- **计算资源**：单GPU（RTX 4090或同级别）

### 6.2 风控约束（横切所有层）
| 约束 | 说明 | 实施位置 |
|------|------|---------|
| 单品种最大持仓 | 不超过账户权益的30% | 环境层：硬约束（action clipping） |
| 单笔止损 | 不超过2% | 执行层：硬止损 |
| 日亏损超5% | 停止交易 | 风控层：熔断 |
| 连续3日亏损 | 人工复核 | 风控层：报警 |
| 杠杆上限 | 不超过3x | 环境层：硬约束 |
| 最低保证金余量 | 不低于维持保证金120% | 环境层：过早终止条件 |

### 6.3 数据约束
- tick数据来源：CTP/SimNow（主力合约连续）
- 需处理：主力合约换月、涨跌停板、盘中暂停
- 数据质量：每批次完整性校验，缺失率 < 0.1%
